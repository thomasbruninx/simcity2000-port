**Disproven**: initial assumption that SC2 chunks are word-padded (they are not).
**Remaining questions**: sprite pixel format; `MISC` layout; sim timer period; RNG algorithms; exact music playlist; `SCURKUSA.DLL` timestamp anomaly; type-240 resource record layout.
**Next**: (1) Ghidra project with sc2kfix leads applied as *labels flagged "unverified"*; (2) trace `large.dat` string xref → sprite decoder; (3) find `timeSetEvent` call → sim tick; (4) find RNG via sc2kfix names; (5) `MISC` field map from load routine.

### Session 2 addendum — sim clock
- mm-timer callback (0x40CA90) only does `PostMessage(hwnd, WM_TIMER, 1, 0)`; so ticks arrive as window messages (VERIFIED). Matches sc2kfix's flag model: `SimulationTicking` is set by the timer path and cleared after each tick except at the fastest speed ("African Swallow"), speeds enum 1=paused,2=turtle,3=llama,4=cheetah,5=swallow (sc2kfix, UNVERIFIED in our build; in 1996 code).
- Only direct `StartSimTimer` call uses 200 ms / 200 ms (VERIFIED call). The mapping speed → effective ticks/sec is therefore NOT a timer period but must be in the WM_TIMER handler (still to find). **HYPOTHESIS:** base tick 200 ms, speed gates how often the sim runs per tick.
- App state machine 0x405A70 documents intro timing (presents 5 s, title ≈5 s).
- Ghidra auto-analysis misses some code (e.g. 0x40CA90, 0x409DC0 not in functions; timeKillEvent xrefs empty). Use `tools/ghidra/Disasm.java` for forced disassembly, and consider a re-analysis pass with code-scan options.
- **Next:** find WM_TIMER handler (message map entry for 0x113 in CSimcityApp/MainFrame), speed variable at app+? and its consumers; MIDI player 0x480BCE/0x480CEB; RNG.

## 2026-10-12 — Session 9: zone types 7–9
Ported `placeZoneBuilding` (0x437C30), `clearSpecialBuilding` (0x438C20), `placeSpecialBuilding` (0x440600) and the military / airport / seaport / subway-decay branches of the zone pass (docs/simulation/special-zones.md). **427/427 emulator runs identical** (61 cities × 7 variants incl. painted 7/8/9 zones).
**Findings:** (1) 0x440600 rejects any tile whose zone nibble is already 7, so 1×1/2×2 military buildings and pier heads are *never* placed on zone-7 tiles by the growth code (original behaviour; the pass still consumes the same rand calls); runways and the 3×3 command centre bypass that check. ## 2026-10-12 — Session 10: thing system
Ported the thing frame update (0x450210) with all nine per-type updaters, eleven spawners, fire/flood helpers and the microsim/label allocator (`src/simulation/things.cpp`, docs/simulation/things.md). **238/238 emulator runs identical** (61 cities × 4 variants × 160 frames, compared after *every frame*), zone (427) and destroy (122) runs still identical with live spawners.
**Findings:** (1) **things are updated by the view's idle handler 0x407160 every 30–45 ms of wall-clock time, not by SimulationTick** — the original's frames-per-day depends on the machine; a driver must choose a policy. (2) The earlier hook names were swapped: 0x452EF0 spawns *trains* at rail stations (0xED), 0x452CE0 *sailboats* at marinas (0xF8). (3) The decompiler mixed two stack variables in the ship update (0x4560B0 state 0); the emulator diff found it (pier-head probe uses the ship's own `b`). (4) A monster of variant 3 builds building 200, which allocates a microsim record: `allocateMicrosim` had to be ported after all. (5) The original reads outside its row tables at the map edge (visitor state 1 even uses `a` twice for both coordinates). (6) Drawing code consumes `rand()` depending on the player's zoom level, so the original is not deterministic across zoom levels; the port omits it.
**Next:** economy model 0x4686C0 and the event half of 0x467AE0 (random fire spread, advisor messages, weather), then the headless 25-phase driver.

## 2026-10-13 — Session 13: terrain, highways, tunnels; budget window; original bitmaps
**Ported and diff-tested:** terrain raise/lower/level (0x443610/0x443DF0/0x442BB0 + 0x443660/0x443B70/0x445500/0x446E30), highway tool (0x461B80 and its planner 0x461370/0x461460, classifier 0x4639D0, piece chooser 0x4622A0, placer 0x462860, bridges 0x45BB30), tunnel 0x44B820, onramp 0x441160, rail link 0x441530, hydro dam 0x440DB0 — 20 runs x 800 operations on 10 cities identical (`EXTENDED=1 sc2k-emu-diff tools`).
**Findings:** (1) **every `classifier == 0x8000` test in the highway code is a sign-extended compare and never true** — the decompiler printed it as a short compare; only the diff exposed it (lesson: never trust a decompiled `short` comparison with 0x8000/0xFFFF constants, check the `MOVSX`/`CMP`). (2) The highway bridge never charges money. (3) The hydro dam charges 400 (table[3]), not the 0 a mis-scaled read suggested. (4) Terrain tools use a FIFO flood queue (the same ring as the water flood) and `UnionRect`, which ignores empty rectangles — the emulator needed native stubs for `SetRect`/`UnionRect` (new `Emu::nativeImport`).
**UI resources:** `PeResources` now reads dialog templates and named bitmaps. The Budget dialog (102) and Ordinances dialog (119) give the row/ordinance labels; ordinance bit order follows the community patch (sales tax, income tax, gambling, parking fines, volunteer fire, smoking ban, clinics, junior sports, reading, anti-drug, CPR, watch, tourist ad, business ad, beautification, carnival, energy, nuclear free, homeless shelter, pollution) and is consistent with the verified cost table (bits 0–3 are income). Tax rates step 1 (0–20), funding 5 (0–100) per the community help text; settlement is `yearToDate / (divisor * 12)`, the window's "to date"/"year end" columns are derived from it (year end = port estimate). The toolbar strip is resource 2 (34 icons of irregular width, found by column segmentation), terrain strip resource 207 (19 px cells), advisors 197–204 (64x82), book/advice/check buttons are named bitmaps.
